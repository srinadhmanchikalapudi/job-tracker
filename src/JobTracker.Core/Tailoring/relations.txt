# How one requirement can be evidenced by wording that is not its name. One rule per line:
#   Target :: strong|partial|related: alternative ; alternative ; ...
# An alternative is one or more things joined with " + ", all of which must be on the same resume line. A thing is either a skill name from
# skills.txt (with all its spellings) or a "quoted phrase" (ignores case; a trailing * lets the word go on: "claim*").
#   strong  - saying this means the person has done the target (Terraform is infrastructure as code). Counts almost fully.
#   partial - closely related wording ("serverless" on Azure for Azure Functions). Counts half, and is shown as a partial match.
#   related - adjacent work worth pointing out ("App Service" for Azure Functions). Never scored; it is shown as potential evidence only.
# Nothing here ever puts a skill into a resume. These rules only decide how the existing resume is read.
